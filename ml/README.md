# ML: признаки и прогнозирование

`backend/prediction_worker.py` читает данные, вызывает функции этого пакета,
измеряет время каждого этапа и сохраняет признаки и прогноз одной транзакцией.
Пакет `ml` не обращается к БД и не запускает фоновые процессы.

## Работа DS

Размещайте модули обработки, вычисления признаков, загрузки моделей и инференса
внутри `ml/`. Для дополнительных модулей используйте импорты вида
`from ml.my_model import ...`. Подключайте их через `pipeline.py` и `predictor.py`:

1. Добавьте подготовку данных в `generate_features(event)` в `pipeline.py`.
2. Подключите модель в `predict_catboost(features)` или `predict_torch(features)`
   в `predictor.py`; переключение и baseline уже находятся внутри `predict`.
3. Сохраните описанные ниже форматы входа и результата. Если они меняются,
   согласуйте изменения с кодом хранения и API.
4. Добавьте зависимости в корневой `requirements.txt`, проверки — в `tests/`.

Цепочка одного цикла: worker → `generate_features` → `predict` → сохранение.
Worker вызывает каждый этап один раз при наличии свежего события. Внутри
`predict` запускается выбранная модель, а при её ошибке — baseline.
Из модулей `ml` не нужно повторно вызывать worker или запускать цикл расчёта.
При импорте модулей не запускайте обучение или инференс; обучение оформляйте
отдельной функцией или командой.

## Пайплайн обработки: `pipeline.py`

`generate_features(event)` принимает событие с полями `state`, `delay`,
`event_at` и возвращает словарь `state`, `delay`, `data_as_of`.
Сейчас обработка только переносит значения; сюда добавляются преобразования
и вычисление признаков. При изменении структуры признаков нужно согласовать
её с предиктором и сохранением признаков в worker.

## Предиктор: `predictor.py`

`predict(features)` — единственная точка входа для получения прогноза.
Возвращает словарь с `state` и `delay`.

Выбор задаётся переменной окружения `MODEL_TYPE`, читаемой при запуске:

- `baseline` (по умолчанию) — `predict_baseline`, исходные состояние и задержка;
- `catboost` — `predict_catboost`;
- `torch` — `predict_torch`.

При исключении модели или неизвестном `MODEL_TYPE` функция использует baseline.
Причина переключения и источник прогноза записываются в лог. Ошибка самого
baseline передаётся worker; частичный результат не сохраняется.

CatBoost и Torch пока не подключены: их функции выбрасывают
`ModelUnavailableError`. Для подключения модели замените соответствующую
функцию загрузкой модели и инференсом, сохранив формат результата. Новые
зависимости указывайте в `requirements.txt`. При необходимости вынесите
реализации моделей в отдельные модули внутри `ml`.

Worker измеряет `features_ms` вокруг `generate_features`, `predict_ms` вокруг
всего `predict` (включая запасной расчёт), `total_ms` — для полного цикла с БД.
