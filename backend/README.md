# Backend

Общий запуск — в [README](../README.md). Три процесса используют одну SQLite-базу:

1. `ndtp_ingestion.server` принимает и проверяет NDTP, сохраняет телеметрию и очищает историю. Актуальный план загружается отдельно, без фактического прибытия.
2. `ml.worker` по таймеру пишет прогнозы.
3. `backend.api:app` читает готовые прогнозы и данные транспорта; `/vehicles/active` добавляет оценку текущей задержки по GPS/плану, не вызывает модель.

Интерфейс показывает все ТС со свежей телеметрией, даже без прогноза или плана. Номер маршрута неизвестен; ID транспорта не выдаётся за номер маршрута. Задержка — оценка, не факт прибытия. Остановка рядом определяется по радиусу 60 м; иначе показывается следующая по плану.

Исторический режим использует время последней точки, живой — текущее UTC. План/телеметрия читаются для окна расчёта, HTTP не записывает данные. `/health` подтверждает только жизнь HTTP-процесса.

Реализация, ограничения и сроки очистки — [ndtp_ingestion/README.md](../ndtp_ingestion/README.md). [INGESTION_REQUIREMENTS.md](INGESTION_REQUIREMENTS.md) содержит исходный проект контракта, а не описание всех гарантий реализации.
