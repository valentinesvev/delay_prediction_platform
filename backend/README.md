# Backend

В рабочей схеме три процесса:

1. **Обработчик входа** принимает NDTP, проверяет пакеты, сохраняет телеметрию и план, удаляет устаревшие входные данные и прогнозы. Пока не реализован; подробный контракт — [INGESTION_REQUIREMENTS.md](INGESTION_REQUIREMENTS.md).
2. **`python -m ml.worker`** по таймеру читает общую БД и пишет прогнозы для парка в `predictions`. Не удаляет записи.
3. **`backend.api:app`** читает `predictions` и отвечает интерфейсу. Он не рассчитывает прогноз и не записывает данные в БД.

Запуск и описание HTTP-ответов — в [корневом README](../README.md). Для локальной проверки обработчик входа заменяет импорт исторического CSV командой `python -m ml.csv_to_db`; это загрузка данных, а не приём NDTP в реальном времени.
